# 🛡️ Security Policy

We are committed to maintaining the security of the **MultiSales** application and greatly appreciate the efforts of security researchers who responsibly report vulnerabilities.

---

## Supported Versions

The following versions of MultiSales are currently supported with security updates. Users are strongly encouraged to upgrade to the latest actively maintained version (currently 5.1.x) to ensure they receive all security patches.

| Version | Supported | Maintenance Status |
| :------- | :--------: | :--- |
| **5.1.x** | :white_check_mark: | **Actively Maintained (Full Support)** |
| **5.0.x** | :x: | End-of-Life (No support) |
| **4.0.x** | :white_check_mark: | **Security-only Maintenance** |
| **< 4.0** | :x: | End-of-Life (No support) |

---

## Reporting a Vulnerability

Please report security vulnerabilities using our dedicated private channel. **Do not create public GitHub issues** for security concerns.

### 1. Private Disclosure Channel

To report a vulnerability, please send a detailed email to:

📧 **`security@multisales.com`** (Replace this with your actual dedicated security email)

### 2. Required Information

To help us triage and fix the issue quickly, your report should include:

* **Vulnerability Description:** A clear, concise summary of the issue.
* **Affected Components:** Specify the application area (e.g., Flutter web app, Firebase Functions, GoRouter guards).
* **Affected Version:** The exact version (e.g., `5.1.0`) where the vulnerability was found.
* **Steps to Reproduce:** Detailed instructions and a Proof of Concept (PoC) demonstrating the vulnerability.
* **Security Impact:** Explain the potential risk to users or the system.

### 3. Our Commitment (Response & Timeline)

We commit to a timely and responsible vulnerability management process:

| Stage | Expected Timeline | Action |
| :--- | :--- | :--- |
| **Initial Acknowledgment** | Within **48 hours** (2 business days) | We confirm receipt of your report. |
| **Triage & Validation** | Within **5–10 business days** | We validate the issue, assign a severity level, and provide an estimated fix timeline. |
| **Patch Release** | Varies (Typically **7–30 days**) | We will notify you when the fix is released. |

We kindly ask that you keep the vulnerability confidential until we publicly release the patch. We will credit you in our security advisory notes upon disclosure, unless you request anonymity.
